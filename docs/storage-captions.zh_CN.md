# 存储与字幕字库优化 — 2.6.8

应用分区从 0x2C0000 扩展至 0x2E0000 字节。`voice_data` 从 0x2D0000 移至
0x2F0000，缩小 128 KiB。`voice_tail`、NVS、PHY 和两处工牌分区的地址、大小
均保持不变。726 段 Opus 音效逐字节保留，逻辑音效流按新边界重新拆分，头部和
有效载荷之后剩余 50,800 字节。旧设备安装前必须完整备份并校验，再分段迁移；
仅写入应用不能完成此次布局调整。安装器校验允许的旧布局，校验新资源后最后写
分区表，并在启动前核对用户数据原始字节。保留数据的升级不可直接刷完整镜像。

三个页面的 14px 字体共用位图和描述表。`assets/fonts/ui14-characters.txt`
保留原字符集合，各字体入口名不变。回归数据核对每个旧字形的像素、宽度、边界
和偏移。使用现有 Noto Sans SC TTF 运行原 14px 生成脚本或
`tools/generate_shared_fonts.py`，即可重新生成共享字体；需要 Pillow。

小智字幕保留 GB2312，补充常见姓名/UI 用字、标点和符号，共 7,783 个字形。
生成前核对源字体的 cmap，`tools/generate_xiaozhi_font.py` 还需要 fontTools。
这并非完整 Unicode 字库。识别、回复和提醒的显示文字在 LVGL 刷新循环外处理：
常见表情显示中文名称，其他图画表情显示 `[表情]`；缺少字形的字符显示
`[U+XXXX]`，补充平面字符使用更长编号，避免悄悄删掉生僻姓名。真正的汉字“口”
保持原样。变体选择符、连接符、肤色修饰符不再显示缺字框；非法 UTF-8 明确显示
编码错误提示。缓冲区截断不会切开 UTF-8 字符或替代提示。音频及服务端对话不变。

## 验证

发布应用为 2,674,896 字节，剩余 339,760 字节（331.8 KiB）。相比 2.6.7，
程序减少 21,216 字节，应用余量增加 152,288 字节。这是闪存余量，不是运行内存。

主机检查覆盖严格 UTF-8、输出边界、表情/未知字符、全部旧 UI 字形像素、全部
GB2312 字符、音效 CRC 和新拆分边界、允许的迁移布局。原生 LVGL 检查确认全部
7,783 字形无占位描述符，并绘制混合字幕。编译和主机绘制不能证明用户某次云端
回复或实机传输正常；设备安装结果需单独报告。
