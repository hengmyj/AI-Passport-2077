# 2.6.35 功耗与异常恢复

本版适配 [FoloToy/ai-passport 31759c4](https://github.com/FoloToy/ai-passport/tree/31759c4d63dd0d0d6580d6f74639ed5315bcd2c3) 的音频恢复和 BSP 资源保护，保留本项目的音频任务归属、音量、屏幕采集、十行显示缓冲、后台语音唤醒及深睡按键唤醒。

## 音频

- 控制与数据接口保留被 codec-dev 忽略的错误，包括被 RX 成功结果覆盖的 TX 失败。
- 休眠先删除 codec 对象，再执行完整 ES8311 休眠序列和读回校验，最后停止 I2S。共享 I2C 和 I2S 资源保留，供唤醒使用。
- 唤醒和格式切换通过公开 API 重建 codec，恢复保存的格式与音量；失败撤销 PCM 访问，并再次停止 I2S、强制休眠。codec 引用释放不可靠时禁止继续重建，需重启恢复。
- 保留 `bsp_audio_init()` 对已初始化休眠设备的唤醒语义。`bsp_audio_is_sleeping()` 表示休眠已验证；`bsp_audio_needs_wake()` 同时覆盖打开或休眠中途失败。
- 休眠失败返回错误，后续调用可以重新尝试。跨任务查询的状态使用原子变量；生命周期与 PCM 操作仍由单个、退出时已完成交接的任务负责。

## 音频任务交接与重试

`badge_power_leave()` 返回真实休眠错误，同时释放任务归属；工作任务不会因为硬件故障而无限等待退出。主循环最多每秒重试一次无人使用的音频休眠，互斥锁同时覆盖检查、休眠操作和任务进入／退出。新任务先取得归属再初始化或恢复音频；主线程内的启动准备与主循环维护串行执行。定时提醒铃声也使用同一套音频归属机制。

只有确认音频休眠成功后才释放音频性能锁。后台语音唤醒仍保留麦克风链路，正常息屏不会关闭正在工作的唤醒词检测。

只有主循环改变屏幕状态。若屏幕休眠失败，且回滚恢复也失败，系统记录真实暂停状态并继续重试唤醒，保留亮度恢复兜底。电源管理初始化失败时释放已申请及持有的性能锁，允许后续重试。

## 资源生命周期与关机

按钮删除失败且仍存活时，保留它使用的 ADC 和校准资源。LVGL 显示注册失败保留已初始化的 port 供重试；port 初始化中途失败时要求重启，避免与异步释放竞争。显示、圆角回调和任务识别定时器在同一把锁内注册，任何失败都不发布半初始化的显示句柄。

系统关机（包括小智关机工具）保持 CW2017 → ES8311 → I2S → 共享 I2C → LCD → 深睡顺序，补充逐步引脚和屏幕关闭错误日志。单个外围设备停止失败后仍尝试其余步骤。唤醒配置或屏幕加锁失败时沿用重启恢复机制。

CW2017 的模式切换、profile 时序和休眠读回沿用上游逻辑。深睡唤醒后会重新激活电量计；芯片重新估算期间返回的临时 `0.00%` 不再当作真实电量，固件等待有效 SOC，并在运行中保留最近一次有效值。若初始化暂时失败，主循环会继续重试。普通息屏不休眠电量计。开启语音唤醒时保留麦克风、I2S 和检测计算，息屏不等于整机深睡。本板无独立 PA 控制引脚，codec 休眠不代表切断外部功放供电。

## 验证

主机测试覆盖音频控制／数据故障注入、64 次格式切换和睡醒后的音量保持、释放失败、ADC 保留、LVGL 初始化和恢复失败、无人使用时重试／新任务排除、电源管理初始化失败、后台唤醒及提醒／屏幕行为。已有较完整主机测试套件也已通过。

`BADGE_BSP_POWER_PROBE` 是可选实机启动测试：十二次 codec／显示睡醒，交替 8/16kHz 格式，静音播放、读取后丢弃麦克风样本，以及音量／亮度检查。正式固件必须关闭该开关。该测试不保存或发送录音，也不测量电流。

准备时 USB 设备不可见，实机验证与实际电流测量尚待完成，未量化续航提升。分区及持久化配置格式不变。
